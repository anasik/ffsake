# FFSAKE v0.1.0-alpha.1

First public alpha candidate. FFSAKE gives coding agents scoped reads, one-call
debugging, a reviewed and journaled editor, selective semantic operations, and
MCP capabilities such as Git review and project tasks. Native Edit/Write remain
available; FFSAKE's transaction guarantees cover edits applied through
preview/apply.

## Highlights

- **CLI-first setup with optional MCP.** `configure --cli-first` installs
  project guidance and a Claude read hook or OpenCode read plugin, and keeps the
  MCP server registered for Git, tasks, access grants and persistent debug
  sessions. Existing host settings are preserved. OpenCode setup writes no
  `permission` entries: existing policies stay byte-for-byte unchanged and
  missing policies stay missing.
- **Reviewable edits.** Preview writes nothing; apply rechecks content and
  stale state; applied changes form one journal transaction with undo/redo.
  Native host edits remain outside this journal.
- **Debugging.** One-call and multi-stop `ffsake probe`, with debugpy and
  netcoredbg launch validated locally. Adaptors are not bundled.
- **Selective language intelligence.** Rust and C++ references, definitions,
  symbols, diagnostics and rename proposals through installed language servers.
  The one-shot CLI can preview and apply a semantic rename with source-hash
  guards. Macro-expanded, `cfg(test)`, integration-test and dependency code can
  be outside the snapshot; always run the project build and tests.
- **Straightforward lifecycle.** Review/apply configuration, `doctor
  --cli-first`, explicit updates with retained rollback generations, project
  removal that preserves unrelated settings, and binary uninstall.

## Install

Install the published release and configure one project:

```sh
git clone --depth 1 https://github.com/anasik/ffsake.git "$HOME/.local/src/ffsake"
python3 "$HOME/.local/src/ffsake/scripts/ffsake_install.py" install \
  --version v0.1.0-alpha.1
python3 "$HOME/.local/src/ffsake/scripts/ffsake_install.py" \
  configure --host claude --project "$PWD" --cli-first --apply
python3 "$HOME/.local/src/ffsake/scripts/ffsake_install.py" \
  doctor --host claude --project "$PWD" --cli-first
```

Use `--host opencode` for OpenCode. MCP-only setup omits `--cli-first`.
FFSAKE does not grant permissions; allow the CLI commands and MCP server in
your host policy (for Claude Code, `Bash(ffsake:*)` covers the CLI). OpenCode
receives no generated permission entries; approve its tool calls normally.

For a source build instead of the published binaries, add `--source
--profile release` to `install`.

## Compatibility

- macOS ARM64 (macOS 14+) and Linux x86-64 (glibc 2.35+).
- Git for Git operations; Python 3.11+ to run the installer.
- Rust/Cargo and a C compiler only for source builds.
- Language servers and debug adapters are separate optional dependencies.
- Windows is not supported.

## Limitations

- Native Edit/Write changes cannot be undone through FFSAKE.
- Host permissions remain authoritative; task execution is not sandboxed.
- Semantic analysis is explicitly incomplete; language-server acceptance is not
  compiler or semantic correctness.
- The Apple LLDB adapter failed its C++ launch test; use a validated adapter.
- Alpha interfaces may change.

## Verification

The release workflow refuses to package or publish a tag unless `ci.yml`
reported success for that exact commit. It then builds both archives, runs
`scripts/alpha_release_smoke.py` against each one, regenerates `SHA256SUMS`
from the uploaded artifacts, and re-checks CI immediately before creating the
prerelease.

The release publishes:

- `ffsake-v0.1.0-alpha.1-macos-arm64.tar.gz`
- `ffsake-v0.1.0-alpha.1-linux-x86_64.tar.gz`
- `SHA256SUMS`

Both archives contain exactly `ffsake` and `ffsake-mcp`. The macOS files are
Mach-O arm64 and the Linux files are ELF x86-64. Verify a download with:

```sh
sha256sum -c SHA256SUMS
```

Checks run for this candidate:

- Both package jobs ran `scripts/alpha_release_smoke.py`: archive checksum,
  unpack validation, clean release generation, Claude and OpenCode
  `configure --cli-first` with pre-existing settings, `doctor --cli-first`,
  packaged-CLI read/preview/apply/undo, project removal and uninstall.
- `scripts/alpha_install_smoke.py` on this machine: source install, repeat
  install, update, rollback, three-host MCP configuration, CLI-first
  Claude/OpenCode setup, preserved settings, project removal, installed-CLI
  end-to-end edit and safe uninstall.
- `scripts/cli_setup_smoke.py`: OpenCode configuration bytes and permission
  policy unchanged, including a project with no `permission` key.
- `scripts/cli_semantic_smoke.py`: real rust-analyzer rename preview/apply,
  shadowing isolation, stale-source rejection and byte-exact undo.
- Exact-head CI for the release commit.

The macOS archive is not notarized and the binaries are not code-signed.
