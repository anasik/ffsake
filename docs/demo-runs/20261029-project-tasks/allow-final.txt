## Friction
- **Cancelling fast tasks:** a warm incremental build finishes in under a second, which is faster than two tool calls in a row. Since a job ID only comes back after the run starts, a quick task can't reliably be cancelled. I registered `SlowSleep` to get a reliable demo. It is still registered and authorized in `.vscode/tasks.json`, which also now contains Build and Test. You may want to remove it.
- **Waiting on results:** `run_task` returns right away and there is no way to wait for a job to finish. I polled jobs 1, 4 and 5 twice each before they completed.
- **Cancellation uses SIGKILL:** the process gets signal 9 straight away, with no SIGTERM first, so a task like `dotnet` has no chance to clean up. The tool description says that processes that deliberately detach from the group won't be stopped. Child processes that `dotnet` leaves running in the background, such as MSBuild nodes, might also survive. I didn't check that.
- **Re-registering is easy:** using the same label replaces the old definition, and the next run uses the new arguments. Nothing marks that the definition changed apart from the new fingerprint.
- **Undo was smooth:** restoring the source took a single `undo` call on the edit's transaction ID, with hash checks.
- **Leftover files:** the builds and test runs created `bin/` and `obj/` in the project folder. They aren't journaled, so undo won't remove them. Every task result says `sandboxed: false` and `journaled: false`.
