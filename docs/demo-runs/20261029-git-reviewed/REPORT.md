# Selected-file Git acceptance — 2026-10-29

Claude Code 2.1.312 used only FFSAKE core MCP tools on a disposable repository with Git mutation explicitly allowed in its host settings. Git was Apple Git 2.39.5. The fixture had an unrelated file with both staged and unstaged changes. Claude read and changed `calculator.txt`, reviewed and staged it, reviewed the exact staged diff, and committed it. The resulting commit `0c79ea7` contained only that file. Independent host Git inspection confirmed that `other.txt` retained its original staged and unstaged changes. See [tool calls and results](tools.json) and [agent answer](answer.txt). This exercise tested deliberate host allowance; it did not observe a normal approval prompt in Claude, Codex or OpenCode.

Reproduce the backend tests with `cargo build --locked --bin ffsake-mcp` and `python3 scripts/git_write_smoke.py target/debug/ffsake-mcp`. The MCP integration covers selected staging, unstaging and commits; preservation of unrelated staged and unstaged work; stale HEAD/index/content rejection; failed branch updates; unborn branches, linked worktrees, spaces and newline/pathspec-like filenames; executable hooks, filters, signing and fsmonitor refusal; and assume-unchanged and skip-worktree flags. An index refresh may invalidate a review; the test explicitly retries only that rejected review. The compare-and-swap update protects the reviewed branch object ID; arbitrary concurrent filesystem writes are not locked.

FFSAKE uses Git plumbing to construct a tree from HEAD and selected index entries, preserving the real index, and refuses executable hooks, signing and selected clean/process filters rather than bypassing them silently. Detached HEAD commits are unsupported. Git operations are not editor transactions or a sandbox, and errors/timeouts can have an uncertain outcome.
