# Subagent worktree acceptance, 2026-10-30

Codex CLI 0.163.0 on macOS was started in a disposable linked worktree with a separately configured FFSAKE server and an explicit startup test policy. Its parent delegated to a real child. The child discovered the MCP tools, checked `ffsake_workspace_info` against `pwd`, read the source and test, previewed and applied `return left - right` → `return left + right`, and ran the named `test` task. The task reported one passing unittest and exit 0. Independent Git inspection found the original checkout unchanged and the child diff limited to that source change and the intentional root-only configuration change. The child's later Git diff call was denied by the host; the independent inspection is not presented as its observation.

[Child calls and results](success-child.json) and [parent output](child5-parent.jsonl) are filtered traces from the synthetic fixture; long discovery output is truncated. Only the fixture's required tools were explicitly approved on the parent command line; the fork did not create those exceptions. An earlier child confirmed the correct root but stopped when `ffsake_read_files` was denied by the host's `never` approval policy: [trace](denial-child.json), [parent output](child4-parent.jsonl). Another run stopped at root inspection under the same policy. An ephemeral Codex session could not spawn a child because the host reported no saved rollout. These are host behavior observations, not a guarantee for all versions or settings.

The parent agent itself ran in the linked child worktree. We did not demonstrate a parent in the original checkout automatically spawning and connecting a child in another worktree. MCP has no caller-worktree identity in tool requests; shared connections stay rooted where started. Claude was not authenticated, and a real OpenCode child was not exercised. See [host limits and setup](../../SUBAGENTS.md).

Reproduce the independent, model-free two-worktree MCP check with `python3 scripts/worktree_mcp_smoke.py target/debug/ffsake-mcp` after building the server. It starts separately rooted servers, checks their identities, reads, edits and runs a configured task, and verifies the original checkout. `python3 -m unittest tests.test_worktree_rebind` tests host configuration rebinds, permission preservation, idempotence and rejection cases. Real model behavior and host approval remain host-dependent.
