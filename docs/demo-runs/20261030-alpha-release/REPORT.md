# Alpha release and update-notice evidence

A fresh Codex CLI session was given a disposable project and a server installed under the stable `current` symlink. The release manifest and shared cache were synthetic: installed `v0.1.0-alpha.1`, cached latest `v0.1.0-alpha.2`. The user prompt asked only for a project summary. The first `ffsake_list` result contained the structured update notice; the agent reported both versions, the explicit installer update step, and MCP reconnection, without installing anything. [Trace](agent-notice.jsonl). This tests agent handling of a synthetic cached notice; it is not evidence that either release was published or that a network check succeeded.

`python3 scripts/update_notice_smoke.py target/debug/ffsake-mcp` tests an actual MCP server through the stable symlink using a fresh synthetic cache, including once-per-session delivery and pin suppression. `python3 -m unittest tests.test_release_install` exercises synthetic release responses and real MCP binaries for installation, repeated install, explicit upgrade, checksum failure, retained generation and rollback. `scripts/release_package.py` packages native binaries, extracts them using the installer rules, and tests MCP initialize and tool discovery. The release workflow's manual dispatch builds and tests archives without publishing; tag pushes publish only after both native package jobs succeed.
