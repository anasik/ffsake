# Alpha installation acceptance — 2026-10-29

A fresh Codex subagent received an isolated local repository URL and followed only `docs/INSTALL.md`, using a disposable prefix and project. It built the default release profile on macOS, installed the binaries, previewed and applied Claude project configuration, ran the doctor, and repeated installation and configuration. Both doctor calls initialized MCP and discovered 36 tools without model calls; the repeated commands reported unchanged, and project configuration hashes matched. The [agent evidence](agent-evidence.json) records the commands and results. The release build took 61.49 seconds in this run; that is not a general performance claim. The agent's timing wrapper accidentally assigned zsh's read-only `status` variable after the installer finished, so the initial installer exit code was not captured; the installer reported `installed` and both subsequent doctor calls passed. Cleanup reporting and standard user-scope duplicate detection were added after this run and are covered by the model-free integration suite.

Separate, no-model host CLI checks used isolated configuration directories: Claude Code 2.1.312 recognized the project `.mcp.json` entry as pending approval; Codex CLI 0.163.0 listed the entry after the disposable project was marked trusted; OpenCode 1.19.5 connected to it. No live user configuration was changed. The initial isolated Claude model session lacked credentials, so the agent exercise used a fresh Codex subagent instead. It did not test Claude's interactive trust prompt or a live Claude chat.

Reproduce the model-free lifecycle test with `python3 scripts/alpha_install_smoke.py`. It clones the source locally and uses disposable directories to exercise installation, all three project configurations, preservation and conflict handling, idempotence, initialization and discovery, update without silent upgrade, a running old server across update, and uninstall without deleting a project journal or configuration. The direct doctor does not verify host trust, global/managed overrides, extra environment/cwd overrides, or the active host session.

The agent was given a local `file://` repository URL containing the reviewed source snapshot; network cloning from GitHub was not part of that agent run. There were no published GitHub release binaries at the time of the audit. The documented default is source build; the Linux path is exercised in CI, and Windows is unsupported.
